- 活动价以提交订单时后端校验为准。已下单的实际成交价保存在历史快照中，不因活动结束或后续调价而改变。

活动记录存于 `menu_promotions`，与常规菜单数据分开。管理员接口：`GET /api/menu/promotions`、`PUT /api/menu/promotions/kopi-teh`。后者接受 `starts_on`、`ends_on`、整数 sen 的 `unit_price`、`enabled`，范围固定为上述六款；创建或更新均使用同一个稳定活动标识。

## 管理员标记售罄

1. 登录管理员账户，打开 **设置 → 售罄管理**。
2. 选择主食、小吃、饮料或啤酒分类。
3. 点击项目旁的 **标记售罄**。
4. 员工菜单中该项目保留显示，标示 **SOLD OUT · 已售罄**，按钮不可选。
5. 补货后点击 **恢复供应**。

售罄状态存于服务器，应用重启或重复初始化不会清除。员工手机每4秒刷新菜单。已打开的选项面板会同步禁用加入按钮，草稿含售罄项目时会提示先移除并禁用提交。

后端在新增项目和提交订单时再次检查售罄状态，因此旧页面、网络延迟和直接 API 调用也不能提交已售罄的项目。若一个混合草稿中存在售罄项目，整批提交会回滚，不会保存半批订单或生成部分打印任务。已提交的账单、付款及合法的幂等重试不受影响。

只有管理员可以修改供应状态。变更写入带操作者和前后状态的审计记录。接口：`PATCH /api/menu/items/{id}/availability`，请求体 `{"sold_out": true}` 或 `{"sold_out": false}`。
