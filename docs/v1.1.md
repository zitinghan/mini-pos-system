# Mini POS v1.1 — 可可·南洋咖啡店

KE KE / KOPITIAM · MYR · Asia/Kuala_Lumpur · 20 tables.

## Implemented workflow

Select a table, choose 主食 / 小吃 / 饮料 / 啤酒, configure the relevant options and quantity, add to the cart, then submit. Categories can be mixed in one batch. Further rounds create ADD-ON batches and print only their new items. Payment remains full-table cash, manually verified QR, or other payment. All authoritative line prices and totals use integer sen on the backend.

The warm cream and dark red interface is retained. The cart, bill, history, and tickets show selected modifiers, temperature, package, snack portion, optional notes, and physical beer bottle count. Tables show elapsed dining time from the first submitted order.

## Historical snapshots

Submission revalidates the current backend menu, then freezes names, option names, quantity, unit price, line total, SKU, category, printer group, portion, selected variant, bottles per unit, physical bottle count, and notes. Later menu edits do not rewrite submitted orders or reports. Existing 面粉糕 and 咖喱卤肉饭 menu identities are adopted as 面粉粿 and 海南咖喱饭; existing order names remain unchanged. Idempotency keys continue to protect additions, submission, payment, and reprints.

## Printing

New orders create separate 厨房 and 饮料 tickets, even in single-printer mode. Mains and snacks route to KITCHEN; drinks and beer route to BEVERAGE. Empty stations produce no job and every item appears once. Settings can enable separate stations with independent private LAN IPs and ports. The station jobs share the same table and batch reference. Historical combined jobs remain unchanged.

Tickets show the new Chinese restaurant name, 48-pixel table/item/option text, unique print-job ticket number, order batch, local date/time, NEW / ADD-ON / REPRINT marker, quantity, portion, modifiers, temperature, beer package/bottles, and notes. The renderer also recognizes a CANCEL order-type payload; submitted-order cancellation and refunds remain outside the existing payment workflow. Long lines wrap to the configured width.

The existing transactional queue, mock modes, claims, FAILED/UNKNOWN handling and audited manual retries are retained. A station's reprint does not block the other station's queued job. A reprint gets a new ticket number and keeps the original job history. SENT is transport completion, not physical print confirmation.

## Dining duration and daily reports

Sessions retain UTC `opened_at`, `first_order_at`, `paid_at`, and `closed_at`. The first successful submission sets `first_order_at` once; additional rounds do not reset it. A successful payment records `paid_at` and closes the table in the same transaction.

Dining seconds = paid_at - first_order_at. Only PAID sessions with valid, timezone-aware, nonnegative timestamps contribute to duration statistics. Missing, malformed, naive, negative, and unpaid durations are excluded.

Daily reporting uses payment completion date in Asia/Kuala_Lumpur. It includes total sales, completed sessions, mains/snacks/drinks/beer sales, average spending rounded to integer sen, average/minimum/maximum dining duration and valid-duration sample count, cash/QR/other totals, beer units, and physical bottles. Historical category totals use order snapshots.

## Safe migration and local installation

`backend/alembic/versions/0002_v11.py` follows frozen revision `0001`. It adds variant/menu/snapshot/routing metadata, backfills session times from existing submissions and payments, updates the active-job uniqueness constraint for routing, and copies every original payment field into an equivalent table permitting RM0 settlement. It never drops order, payment, user, or print history. Destructive downgrade remains disabled.

Before applying on any other installation:

1. Stop the application and print worker after any in-flight print finishes.
2. Back up SQLite with its online backup API; retain ticket preview files separately.
3. Run `python -m app.database.initialize` from `backend` in the installed environment.
4. Rebuild the frontend with `npm ci` and `npm run build`, then restart the app.
5. Confirm menu verification flags and printer settings.

On this Windows checkout, `Start-POS.cmd` applies migrations and seeds idempotently. `scripts/verify_v11_upgrade.py` makes a private backup and rehearses migration/seed twice against an isolated copy, comparing every original history field and checking SQLite integrity/foreign keys. Backups and rehearsal data remain ignored by Git.
